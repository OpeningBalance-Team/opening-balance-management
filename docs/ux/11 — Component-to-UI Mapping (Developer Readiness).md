## 1. المنهجية

هذه الوثيقة تربط كل مكون بلومنتات الواجهة البصرية المحسّنة (v2)، وتقدم **Developer Readiness** — وصفًا كافيًا لكل شاشة لتحويلها إلى Blazor Components مباشرة دون إعادة تصميم. أسماء المكونات حرفية من مخطط Component/UI Structure المعتمد؛ لا يُضاف أي Component جديد.

## 2. الخريطة الكلية

| المنطقة البصرية (v2) | المكون | الحالات التي يظهر فيها |
|---|---|---|
| شريط علوي (App topbar) | جزء من `OpeningBalancePage` (Header) | A..L دائمًا |
| شريط الرسائل العالمية | `MessageBox / ValidationMessage` | B (نجاح)، E (خطأ كمية)، H (خطأ تحقق)، I (خطأ حفظ)، J (نجاح حفظ) |
| بطاقة الرأس | `HeaderForm` | A..L دائمًا |

## 3. Developer Readiness لكل مكون

### 3.1 OpeningBalancePage

**Layout:** صفحة واحدة بخلفية `#f3f4f6`؛ شريط علوي كحلي داكن (56px) يحمل اسم التطبيق «نظام إدارة المخزون» وقائمة ترقيم الصفحة؛ ثم حاوية `.page` بعرض أقصى 1392px تحتوي البطاقات الثلاث؛ شريط الحفظ مطلق أسفل الصفحة (sticky-bottom، 76px). **RTL:** `direction: rtl` على `<html>` — الصفحة كلها ترثه. **Responsive:** عند عرض < 1480px تصبح الحاوية بعرض كامل؛ البطاقات نفسها لا تتغير. **الحالات:** تدير `OpeningBalanceSession` (Editing / Validation / Saving / SavedInMemory) وتعرض الرسالة العالمية وفق النتيجة.

### 3.2 MessageBox / ValidationMessage

**Layout:** شريط كامل العرض بحجم 44px بعد الشريط العلوي، بخلفية دلالية (نجاح `#f0fdf4` / خطأ `#fef2f2`) وحد سفلي ملون ورمز دائري (✓/✕) والنص بنمط الغامق. **الحالات:** يختفي عند عدم وجود رسالة (الحالة A). **التفاعل:** بلا تفاعل — عرض فقط. **التحقق:** المحتوى حرفي من التحليل؛ لا نصوص مخترعة. **Traceability:** NFR-04.

### 3.3 HeaderForm

**Layout:** بطاقة بيضاء (زاوية 14px، ظل خفيف) برأس «رأس الوثيقة — Document Header» مع Tag يمين يحمل المرجع FR-01/FR-02؛ جسمها `form-row` بأربعة حقول بترتيب RTL: رقم الوثيقة ← التاريخ ← المستخدم ← البيان. **Label فوق الحقل** بخط 12px رمادي مع «*» أحمر للمطلوب. **الحقل:** 40px ارتفاع، Focus ring أزرق 3px، حقل الخطأ أحمر مع رسالة Inline. **الحالات:** A (فارغ، بيان عليه Hint «ليس شرطًا للصلاحية — قسم 6.7»)، B (ممتلئ بنص غامق). **التحقق:** عند A1/A2 (UC-002) + inline عند blur.

### 3.4 AddDetailRow (+ ProductDropdown / WarehouseDropdown)

**Layout:** بطاقة «سطر الإدخال — إضافة صنف جديد» بخمسة حقول RTL: Product ← Warehouse ← الكمية ← السعر (اختياري) ← تاريخ الصلاحية (اختياري)، ثم زر «+ إضافة» أزرق primary (حجم طبيعي غير مبالغ) — في RTL يظهر الزر يسار الحقول كمنطق صف الإدخال. **المنسدلة:** قائمة منسدلة تحت الحقل بخيارات: المحدد الحالي بخلفية زرقاء ناعمة (C). **الحالات:** C (المنسدلة مفتوحة)، E (خطأ الكمية: حقل أحمر + Inline + Global). **التحقق:** BR-01..05 عند الضغط؛ لا إضافة عند الفشل. **Traceability:** FR-03/04/05، UC-003..005.

### 3.5 DetailsGrid (+ EditDetailRow)

**Layout:** بطاقة «تفاصيل الرصيد الافتتاحي — Balance Details»؛ رأس الجدول رمادي فاتح بحد مضاعف، صفوف بارتفاع مريح وفواصل رفيعة و**Hover** ناعم؛ الأعمدة RTL: # ← الصنف ← المخزن ← الكمية ← السعر ← تاريخ الصلاحية ← الإجراءات؛ الأرقام `tabular-nums` محاذاة يسار LTR. روابط الإجراءات نصية: «تعديل» أزرق / «حذف» أحمر مع Hover ناعم. **الحالات:** A/H (الحالة الفارغة: صندوق متقطع بعلامة ونص «لا توجد تفاصيل...»)، D (صفوف مكتملة)، E (صف خطأ أحمر فاتح)، F (صف EditDetailRow بخلفية تحذيرية فاتحة وحقول مباشرة داخل الصف + أزرار «حفظ التعديل» secondary و«إلغاء» ghost). **Traceability:** FR-06/FR-07، UC-006/UC-007، BR-06.

### 3.6 EditDetailRow

**السلوك البصري:** يتحول الصف نفسه إلى صف تحرير بنفس أعمدة AddDetailRow (الحقول inline داخل الصف، وليس Modal)؛ خلفية تحذيرية فاتحة تميزه عن باقي الصفوف؛ أزرار الحفظ/الإلغاء داخل خلية الإجراءات. **Traceability:** UC-007 A1/A2/A3.

### 3.7 ConfirmDialog

**Layout:** Overlay داكن شبه شفاف (45%)، Dialog بعرض 460px وزاوية 14px وظل عميق؛ رأس «تأكيد الحذف — UC-008» بنقطة حمراء؛ جسم يعرض السؤال الحرفي «هل تريد حذف هذا السطر؟» مع صندوق رمادي يصف السطر (الصنف — المخزن — الكمية)؛ تذييل بأزرار: «حذف — Confirm» (danger، ممتلئ أحمر) ثم «إلغاء — Cancel» (secondary). **Traceability:** FR-08، UC-008 A1.

### 3.8 SaveAction

**Layout:** شريط سفلي ثابت أبيض بظل علوي؛ يمينه ملاحظة رمادية «البيانات محفوظة داخل الجلسة فقط — Mock / In-Memory (FR-09)»، يساره زر «حفظ الوثيقة — Save» بعرض 200px وارتفاع 44px — **العنصر البصري الأبرز** (Primary الوحيد كبير الحجم). **الحالات:** A (معطل رمادي)، H (مفعّل لكن الضغط يفشل بـ A2)، I (مفعّل لإعادة المحاولة — A4)، J (مفعّل بعد النجاح — UC-009 Postconditions)، **L (وضع التحميل: نص الزر «جاري الحفظ...» مع خلفية رمادية معطلة + تعطيل زر الإضافة أيضًا)**. **Traceability:** FR-09، UC-009 A1..A4.

## 4. Responsive Behavior

| العرض | السلوك |
|---|---|
| Desktop (≥ 1480px) | الحاوية 1392px متمركزة؛ form-row بصف واحد؛ الجدول كامل العرض |
| Tablet (≤ 1100px) | الحاوية بعرض كامل؛ form-row يلتف تلقائيًا بحقول بعرض أدنى 160px؛ خط الجدول يصغر |
| Narrow (≤ 640px) | الحقول عمود واحد كامل العرض؛ الجدول داخل حاوية `overflow-x: auto` (تمرير أفقي — سلوك Blazor طبيعي)؛ أزرار الإجراءات full-width مكدسة |

## 5. RTL Behavior

كل الاتجاهات ناتجة عن `direction: rtl` الوراثي: التسميات يمين الحقول، الحقول تترتب يمينًا لليسار، رؤوس الجدول والأرقام، المنسدلة تفتح يمين الحقل، Dialog يفتح متمركزًا، أزرار الـ Dialog تبدأ Confirm يمينًا. لا توجد أي قيم `left/right` صريحة معكوسة يدويًا.

## 6. Validation Presentation

| المستوى | الشكل البصري | متى |
|---|---|---|
| Inline (حقل) | حد أحمر + خلفية حمراء فاتحة + علامة «!» + نص تحته | خطأ الكمية (E)، حقول مطلوبة فارغة (A1) |
| صف الجدول | خلفية حمراء فاتحة (خطأ) / تحذيرية فاتحة (تعديل) | BR-02 عند الإضافة، UC-007 A1 |
| Global | شريط علوي ملون | A2/A4، نجاح B/J، حذف G |

الترتيب الدلالي ثابت: الأخطاء الحمراء لا تتعايش مع النجاح الأخضر، والحالة الفارغة ليست خطأ بل حالة توجيه محايدة.
