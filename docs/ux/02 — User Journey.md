## 2. تحقق الحفظ (UC-009) — تفصيل المرحلة 11

| البوابة | الشرط | الرسالة عند الفشل | سلوك الواجهة |
|---|---|---|---|
| A1 — رأس مكتمل؟ | رقم الوثيقة + التاريخ + المستخدم موجودة، تاريخ صالح | «يرجى استكمال بيانات الرصيد الافتتاحي» | لا حفظ + تحديد الحقول المعيبة |
| A1 (تكرار مشروط) — رقم مكرر؟ | تحقق اختياري من الوثائق المحفوظة (UC-002 A3 / UC-009 A1 — قرار OD-1 مفتوح) | «رقم الوثيقة مستخدم مسبقًا» | لا حفظ + تمكين التعديل |
| A2 — توجد سطور؟ | صف واحد على الأقل | «يجب إضافة صنف واحد على الأقل قبل الحفظ» | لا حفظ + التركيز على سطر الإدخال |
| A3 — كل السطور صحيحة؟ | BR-01..BR-05 على كل السطور | «يرجى تصحيح البيانات» + الإشارة للسطر المعيب | لا حفظ + إبراز السطر/الحقل المعيب |
| A4 — نجاح التخزين؟ | InMemoryRepository يقبل الحفظ | «تعذر حفظ الأرصدة الافتتاحية — إمكانية إعادة المحاولة» | لا حفظ + زر إعادة المحاولة متاح |
| النجاح | كل البوابات تمر | «تم حفظ الأرصدة الافتتاحية بنجاح» (UC-009 Postcondition) | رسالة نجاح + الوثيقة جاهزة للعرض/التعديل داخل الجلسة |

## 3. مبادئ الرحلة (مشتقة من المصدرين)

1. **رحلة واحدة متصلة:** كل مراحل الرحلة على شاشة واحدة؛ لا تنقّل بين صفحات (FR-01/UC-001).
2. **التحقق مبكر وواضح:** عند الإضافة (UC-003) وعند الحفظ (UC-009) — لا تحقق مؤجل مفاجئ.
3. **لا فقدان بيانات:** التعديل يلغى بالعودة للبيانات الأصلية (UC-007)؛ الحذف يتطلب تأكيدًا (UC-008)؛ الحفظ داخل الجلسة مضمون (FR-09).
4. **أسماء لا معرفات:** المستخدم لا يرى ProductId/WarehouseId أبدًا (BR-06).
5. **الخطأ يحدد نفسه:** الرسالة تشير للحقل أو السطر المعيب (NFR-04/NFR-06).
6. **السعر والصلاحية اختياريان:** لا يُطلبان عند الإضافة ولا عند الحفظ (قسم 6.7) — غيابهما ليس خطأ.
