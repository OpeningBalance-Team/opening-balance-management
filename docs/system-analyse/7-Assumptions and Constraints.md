

## 1. Assumptions

الافتراضات هي الأمور التي يُبنى عليها التحليل أو التنفيذ على أنها صحيحة ما لم يثبت خلاف ذلك.

| الرمز | الافتراض | التأثير |
| --- | --- | --- |
| `ASM-01` | المستخدم يملك صلاحية الدخول إلى شاشة الأرصدة الافتتاحية. | لا يتم رفض الوصول بسبب Authorization في النسخة الأولية. |
| `ASM-02` | بيانات الأصناف والمخازن متاحة من خلال `Mock Data`. | يمكن اختبار عمليات الاختيار والإضافة دون Database. |
| `ASM-03` | كل صنف وكل مخزن له معرف داخلي فريد. | يمكن ربط الاسم بالمعرف عند الحفظ أو التعديل. |
| `ASM-04` | الكمية تمثل رصيدًا فعليًا أوليًا وليست حركة بيع أو شراء. | لا يتم تطبيق منطق الحركات المخزنية داخل هذه الشاشة. |
| `ASM-05` | السعر وتاريخ الصلاحية قد يكونان اختياريين حسب طبيعة الصنف. | يسمح النظام بإدخال السجل دون هذين الحقلين إذا لم يكونا مطلوبين. |
| `ASM-06` | المستخدم يعرف الأصناف والمخازن التي يريد إدخالها. | لا يتضمن النظام في هذه المرحلة عملية بحث متقدمة أو اقتراحات ذكية. |
| `ASM-07` | البيانات المدخلة صحيحة من مصدرها التشغيلي. | يركز النظام على التحقق الشكلي وقواعد الإدخال، وليس على المطابقة الميدانية. |
| `ASM-08` | التطبيق يعمل في بيئة تدعم Blazor Web App وInteractive Server. | تعتمد التفاعلية على اتصال مستمر نسبيًا بين العميل والخادم. |
| `ASM-09` | لا توجد تكاملات خارجية مطلوبة في المرحلة الحالية. | لا يتم الاتصال بنظام ERP أو خدمة مخزون خارجية. |
| `ASM-10` | الحفظ الحالي مؤقت داخل الذاكرة. | تعود البيانات إلى القيم الأولية عند إعادة تشغيل التطبيق. |

## 2. Constraints

القيود هي الحدود التي تحد من نطاق النظام أو تؤثر في طريقة تصميمه وتنفيذه.

| الرمز | القيد | الأثر على النظام |
| --- | --- | --- |
| `CON-01` | استخدام `Mock Data` بدل قاعدة بيانات دائمة. | لا توجد استمرارية للبيانات بعد إعادة تشغيل التطبيق. |
| `CON-02` | عدم وجود API خارجي في المرحلة الحالية. | جميع العمليات تتم داخل التطبيق. |
| `CON-03` | عدم تنفيذ Authorization كامل. | لا توجد مصفوفة صلاحيات فعلية بين الأدوار في النسخة الأولية. |
| `CON-04` | الاعتماد على Interactive Server. | تحتاج الواجهة إلى اتصال فعال بالخادم أثناء التفاعل. |
| `CON-05` | نطاق الشاشة يركز على الأرصدة الافتتاحية فقط. | لا تشمل المرحلة الحالية المبيعات أو المشتريات أو التحويلات المخزنية. |
| `CON-06` | عدم وجود Audit Trail دائم. | لا يتم تسجيل تاريخ كل تعديل أو حذف في سجل دائم. |
| `CON-07` | عدم وجود Workflow اعتماد رسمي. | الحفظ لا يمر بمراحل اعتماد متعددة في النسخة الأولية. |
| `CON-08` | البيانات الحالية محدودة لأغراض العرض والاختبار. | لا تمثل Mock Data قاعدة الأصناف الحقيقية بالكامل. |
| `CON-09` | لا يتم تنفيذ رفع ملفات أو مرفقات. | لا يمكن إرفاق مستندات إثبات بالرصيد في المرحلة الحالية. |
| `CON-10` | لا يتم تنفيذ تقارير متقدمة. | يقتصر العرض على شاشة الإدخال والجدول الحالي. |
تيار مخزن. |
| `WF-A06` | كمية صفرية أو سالبة | رفض الإضافة وعرض قاعدة الكمية. |
| `WF-A07` | سجل غير موجود عند التعديل | رفض العملية وعرض رسالة مناسبة. |
| `WF-A08` | سجل غير موجود عند الحذف | رفض العملية وعدم تغيير البيانات. |
| `WF-A09` | إلغاء الحذف | العودة إلى الجدول دون حذف. |
| `WF-A10` | الحفظ دون تفاصيل | رفض الحفظ وطلب إضافة سجل. |
