
# تحليل نظام الأرصدة الافتتاحية للمخزون

> وثيقة تحليلية مركزة تتناول **ملخص الوثيقة، الفكرة الرئيسية للنظام، أهداف النظام ونطاقه، المتطلبات الوظيفية، والمتطلبات غير الوظيفية** فقط.

---

## 1. ملخص الوثيقة

تقدّم هذه الوثيقة تحليلًا شاملًا ومنظمًا لنظام **إدارة الأرصدة الافتتاحية للمخزون**، بوصفه أحد المكونات المحورية في منظومة إدارة المخزون. ويأتي هذا النظام ليمنح المؤسسة قدرة استثنائية على تحويل البيانات الفعلية الموجودة في المخازن عند بداية تشغيل النظام أو عند تهيئته لأول مرة إلى بيانات رقمية منظمة وقابلة للإدارة والمراجعة داخل التطبيق.

يمكّن النظام المستخدم من إنشاء وثيقة رصيد افتتاحي متكاملة، تتضمن البيانات الأساسية للوثيقة مثل **رقم الوثيقة، التاريخ، المستخدم، والبيان**، إلى جانب إضافة تفاصيل الأصناف الموجودة فعليًا في المخازن وتحديد خصائصها الرئيسية، مثل **الصنف، المخزن، الكمية، السعر، وتاريخ الصلاحية عند الحاجة**.

ولا تقتصر قيمة النظام على تسجيل البيانات فحسب، بل تمتد إلى بناء تمثيل منظم ودقيق لحالة المخزون في لحظة البداية. فكل صنف يصبح مرتبطًا بمخزن محدد وكمية محددة، مع إمكانية إدخال المعلومات الإضافية التي تساعد على توثيق طبيعة الصنف، مثل السعر وتاريخ الصلاحية. وبهذا الأسلوب، تتحول البيانات الأولية المتفرقة إلى بنية معلوماتية واضحة يمكن للنظام التعامل معها بصورة موحدة.

كما يوفّر النظام بيئة مناسبة لمراجعة البيانات وإدارتها قبل اعتمادها، إذ يستطيع المستخدم إضافة تفاصيل الأصناف، واستعراضها في جدول منظم، وتعديلها عند اكتشاف أي خطأ، وحذف السجلات التي لم تعد مطلوبة، ثم حفظ البيانات داخل التطبيق وفق نطاق التنفيذ الحالي باستخدام **Mock Data**.

ويُبنى تصميم الواجهة على مبدأ الوضوح وسهولة الاستخدام؛ لذلك يعرض النظام أسماء الأصناف والمخازن للمستخدم بدلًا من الاعتماد على المعرفات الداخلية أو إظهارها بصورة مباشرة. وفي الوقت نفسه، يحتفظ النظام بالمعرفات الداخلية اللازمة للربط والمعالجة خلفيًا. ويسهم هذا النهج في الارتقاء بتجربة المستخدم، وتقليل احتمالات الإدخال الخاطئ، ورفع مستوى قابلية المراجعة والفهم.

### 1.1 البيانات الأساسية للوثيقة

| العنصر | الوصف التفصيلي |
|---|---|
| اسم النظام | نظام إدارة الأرصدة الافتتاحية للمخزون |
| نوع الوثيقة | تحليل متطلبات وحالات استخدام |
| الغرض العام | تسجيل وتنظيم الكميات الفعلية الموجودة في المخازن عند بداية تشغيل النظام |
| نطاق التنفيذ الحالي | إدخال وعرض وتعديل وحذف وحفظ مؤقت باستخدام Mock Data |
| مصدر البيانات | بيانات وهمية داخل الذاكرة، دون اتصال بقاعدة بيانات حقيقية |
| لغة الواجهة | العربية |
| اتجاه الواجهة | RTL |
| المستخدمون المستهدفون | موظف المخزون ومدير النظام |
| طبيعة الواجهة | واجهة احترافية، واضحة، سهلة الاستخدام، ومتوافقة مع مختلف أحجام الشاشات |

## 2. الفكرة الرئيسية للنظام — System Overview

تتمثل الفكرة الرئيسية للنظام في إنشاء نقطة انطلاق موثوقة لإدارة المخزون داخل التطبيق. فعند بدء استخدام النظام، تكون لدى المؤسسة كميات فعلية موزعة على مخازن مختلفة، وقد تكون هذه الكميات موجودة قبل وجود النظام أو قبل تفعيل نظام إدارة المخزون. ومن هنا تنشأ الحاجة إلى وسيلة دقيقة ومنظمة لنقل الواقع الفعلي للمخازن إلى البيئة الرقمية.

يستجيب نظام الأرصدة الافتتاحية لهذه الحاجة من خلال إنشاء وثيقة مركزية تمثل الحالة الأولية للمخزون. وتعمل الوثيقة بوصفها سجلًا أساسيًا يجمع بين **Header** و **Details**؛ حيث يضم **Header** المعلومات العامة التي تعرّف الوثيقة، بينما يضم **Details** جميع الأصناف والكميات والبيانات المرتبطة بها.

### 2.1 مكونات الفكرة الرئيسية

| المكوّن | دوره في النظام |
|---|---|
| Header | يحتوي على رقم الوثيقة، التاريخ، المستخدم، والبيان أو الملاحظات. |
| Details | يحتوي على الصنف، المخزن، الكمية، السعر، وتاريخ الصلاحية عند الحاجة. |
| قائمة الأصناف | توفّر أسماء الأصناف التي يمكن للمستخدم اختيارها، مثل `Laptop HP` و`Mouse Logitech` و`Keyboard`. |
| قائمة المخازن | توفّر أسماء المخازن التي يمكن ربط الأصناف بها، مثل المخزن الرئيسي ومخزن الأدوية ومخزن الأجهزة. |
| جدول التفاصيل | يعرض السجلات المدخلة بطريقة منظمة، مع إتاحة عمليات التعديل والحذف. |
| Mock Data | تمثل مصدر البيانات في مرحلة التنفيذ الحالية، وتُستخدم دون الاعتماد على قاعدة بيانات حقيقية. |
| الواجهة | تقدم تجربة إدخال واضحة باللغة العربية وبتنسيق RTL، مع إظهار الأسماء الوصفية بدلًا من IDs. |

### 2.2 آلية عمل النظام بصورة عامة

تبدأ آلية العمل بفتح المستخدم شاشة الأرصدة الافتتاحية من قائمة النظام. بعد ذلك، يعرض النظام نموذج **Header** لإدخال البيانات العامة للوثيقة، ثم يتيح للمستخدم إضافة أصناف إلى قسم **Details**. وعند إضافة كل صنف، يختار المستخدم الصنف والمخزن، ويدخل الكمية، ويحدد السعر وتاريخ الصلاحية إذا كان ذلك مطلوبًا.

بعد إدخال البيانات، ينفّذ النظام عمليات التحقق اللازمة للتأكد من اكتمال الحقول وصحة القيم. فلا يسمح النظام بإضافة تفاصيل دون اختيار صنف ومخزن وإدخال كمية، كما لا يقبل الكمية التي تساوي صفرًا أو تقل عنه. وبعد نجاح التحقق، يظهر السجل في جدول التفاصيل، بحيث يستطيع المستخدم مراجعته أو تعديله أو حذفه قبل الحفظ.

### 2.3 القيمة التشغيلية للنظام

يقدم النظام قيمة تشغيلية عالية من خلال توحيد طريقة تسجيل المخزون الأولي، وتقليل الاعتماد على الإدخال اليدوي غير المنظم، وإتاحة صورة واضحة عن توزيع الأصناف داخل المخازن. كما يحد من الالتباس الناتج عن استخدام المعرفات الداخلية، لأن المستخدم يتعامل مع أسماء مفهومة وواضحة، بينما يحتفظ النظام بالـ IDs اللازمة للمعالجة الداخلية.

ويمثل هذا النظام أساسًا قويًا يمكن البناء عليه في مراحل مستقبلية، مثل ربط البيانات بقاعدة بيانات حقيقية، أو إدخال عمليات الشراء والبيع، أو تحديث المخزون الفعلي، أو تطبيق الصلاحيات المتقدمة، أو إضافة مراحل الاعتماد والترحيل.
