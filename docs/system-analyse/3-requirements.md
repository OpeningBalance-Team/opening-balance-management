
## 4.3 المتطلبات الوظيفية — Functional Requirements

| الرمز | المتطلب | التحليل |
| --- | --- | --- |
| `FR-01` | عرض شاشة الأرصدة الافتتاحية | تتضمن الشاشة بيانات الوثيقة: رقم الوثيقة، التاريخ، المستخدم، والبيان، إضافة إلى جدول التفاصيل. |
| `FR-02` | إدخال بيانات رأس الرصيد | يسمح النظام بإدخال رقم الوثيقة وتاريخ الإدخال واسم المستخدم ووصف أو ملاحظات. مثال: `OB-001`، `18/08/2026`، بشار، رصيد افتتاحي للمخزن الرئيسي. |
| `FR-03` | إضافة تفاصيل الرصيد | يسمح النظام بإضافة صنف جديد مع تحديد الصنف والمخزن والكمية والسعر وتاريخ الصلاحية. |
| `FR-04` | اختيار الصنف | يعرض النظام قائمة أسماء مثل `Laptop HP` و`Mouse Logitech` و`Keyboard`، مع حفظ المعرف الداخلي خلفيًا. |
| `FR-05` | اختيار المخزن | يعرض النظام قائمة أسماء مثل المخزن الرئيسي ومخزن الأدوية ومخزن الأجهزة. |
| `FR-06` | عرض التفاصيل في جدول | يعرض الجدول الصنف والمخزن والكمية والسعر والصلاحية. مثال: `Laptop HP` | الرئيسي | `50` | `500` | `–`. |
| `FR-07` | تعديل تفاصيل الصنف | يمكن تعديل الصنف والمخزن والكمية والسعر وتاريخ الصلاحية. |
| `FR-08` | حذف تفاصيل الصنف | يمكن حذف أي سطر من الجدول بعد إظهار تأكيد للمستخدم. |
| `FR-09` | حفظ البيانات | تُحتفظ البيانات داخل التطبيق في الذاكرة باستخدام `Data Mock`، ولا يوجد حفظ دائم في قاعدة البيانات ضمن هذه المرحلة. |

## 5.4 المتطلبات غير الوظيفية — Non Functional Requirements

| الرمز | المتطلب | التحليل |
| --- | --- | --- |
| `NFR-01` | التصميم | واجهة احترافية، واضحة، سهلة الاستخدام، ومتجاوبة مع أحجام الشاشات المختلفة. |
| `NFR-02` | اللغة والاتجاه | دعم اللغة العربية واتجاه `RTL` في جميع مكونات الشاشة والجداول والرسائل. |
| `NFR-03` | الأداء | تحميل البيانات بسرعة وعدم وجود تأخير ملحوظ عند إضافة الأصناف أو تحديث الجدول. |
| `NFR-04` | تجربة المستخدم | توفير رسائل نجاح ورسائل خطأ، وتأكيد قبل الحذف، ومنع الإدخال الخاطئ. |
| `NFR-05` | التفاعل | تنفيذ العمليات داخل الصفحة دون إعادة تحميل عند استخدام `Blazor`. |
| `NFR-06` | قابلية القراءة | عرض الأسماء الواضحة للمستخدم وعدم إظهار معرفات النظام `IDs` بدل الأسماء. |
