

## 3. أهداف النظام ونطاقه — System Objective & System Scope

### 3.1 أهداف النظام — System Objective

يهدف النظام إلى تحقيق مجموعة متكاملة من الأهداف التي ترفع جودة إدارة المخزون منذ اللحظة الأولى لتشغيل التطبيق. ولا يقتصر الهدف على توفير شاشة إدخال، بل يسعى إلى بناء عملية متماسكة تضمن الدقة والوضوح وسهولة المراجعة وقابلية التوسع.

| الرمز | الهدف | الوصف التفصيلي |
|---|---|---|
| `OBJ-01` | تسهيل إدخال الأرصدة الافتتاحية للأصناف | تمكين المستخدم من تسجيل الأصناف والكميات الموجودة فعليًا بطريقة مباشرة ومنظمة، بدل الاعتماد على سجلات يدوية أو عمليات إدخال غير موحدة. |
| `OBJ-02` | تنظيم بيانات المخزون عند بداية تشغيل النظام | إنشاء بنية واضحة تمثل حالة المخزون الأولية، وتجمع البيانات العامة للوثيقة مع تفاصيل الأصناف في سجل مترابط. |
| `OBJ-03` | ربط الأصناف بالمخازن والكميات الموجودة | ضمان تحديد المكان الذي يوجد فيه كل صنف، وربطه بكمية محددة داخل مخزن معين، بما يمنح النظام صورة دقيقة عن التوزيع الأولي للمخزون. |
| `OBJ-04` | توفير واجهة سهلة لإدارة تفاصيل الرصيد | تقديم شاشة تفاعلية ومنظمة تسمح بإضافة التفاصيل ومراجعتها وتعديلها وحذفها قبل الحفظ. |
| `OBJ-05` | تقليل الأخطاء الناتجة عن الإدخال اليدوي غير المنظم | تطبيق قوائم اختيار وقواعد تحقق ورسائل واضحة، وعرض الأسماء بدل IDs، للحد من أخطاء الاختيار والإدخال والربط. |

### 3.2 نطاق النظام — System Scope

يحدد **System Scope** ما سيتم تنفيذه في المرحلة الحالية، وما سيتم استبعاده مؤقتًا إلى مراحل لاحقة. ويساعد هذا التحديد على ضبط توقعات التنفيذ، ومنع التداخل بين الوظائف الحالية والوظائف التي تحتاج إلى تحليل أو بنية مستقلة مستقبلًا.

#### 3.2.1 ما يشمله النظام في المرحلة الحالية

| النطاق المشمول | الوصف |
|---|---|
| فتح شاشة الأرصدة الافتتاحية | إتاحة الوصول إلى الشاشة من قائمة النظام، وتجهيز مكوناتها الأساسية لاستقبال إدخال المستخدم. |
| إدخال بيانات رأس الرصيد | إدخال رقم الوثيقة والتاريخ والمستخدم والبيان أو الملاحظات. |
| إضافة تفاصيل الأصناف | إضافة صنف جديد إلى الوثيقة مع تحديد المخزن والكمية والسعر وتاريخ الصلاحية عند الحاجة. |
| اختيار الأصناف | توفير قائمة أصناف واضحة تعرض الأسماء الوصفية، مع الاحتفاظ بالـ ID داخليًا. |
| اختيار المخازن | توفير قائمة مخازن واضحة وربط المخزن المحدد بسطر التفاصيل. |
| عرض تفاصيل الرصيد | عرض الأصناف في جدول منظم يتضمن الصنف والمخزن والكمية والسعر والصلاحية. |
| تعديل البيانات | تمكين المستخدم من تعديل بيانات الصنف والمخزن والكمية والسعر وتاريخ الصلاحية. |
| حذف البيانات | تمكين المستخدم من حذف سجل محدد بعد عرض رسالة تأكيد مناسبة. |
| حفظ البيانات | الاحتفاظ بالبيانات داخل التطبيق باستخدام Mock Data وفي الذاكرة أثناء التشغيل. |
| التحقق من الإدخال | منع القيم الناقصة أو غير الصحيحة، وإظهار رسائل خطأ واضحة للمستخدم. |
| دعم الواجهة | دعم اللغة العربية واتجاه RTL، مع تصميم Responsive وسهل الاستخدام. |

#### 3.2.2 ما لا يشمله النظام في المرحلة الحالية

| النطاق غير المشمول | التوضيح |
|---|---|
| الربط مع قاعدة بيانات حقيقية | لا يتم في هذه المرحلة تخزين البيانات بشكل دائم داخل قاعدة بيانات فعلية. |
| عمليات الشراء والبيع | لا يتضمن النظام إدارة أو تسجيل دورات الشراء والبيع. |
| تحديث المخزون الفعلي | لا يقوم النظام في هذه المرحلة بتنفيذ ترحيل فعلي أو تحديث دائم لأرصدة المخزون التشغيلية. |
| إدارة المستخدمين والصلاحيات بشكل كامل | لا تشمل المرحلة الحالية بناء منظومة كاملة لإدارة المستخدمين والأدوار والصلاحيات. |
| مرحلة الاعتماد والترحيل | لا توجد عملية اعتماد رسمية أو ترحيل للرصيد إلى دورة المخزون النهائية في النسخة الحالية. |

### 3.3 حدود التنفيذ الحالية

يعتمد النظام في صورته الحالية على **Mock Data**، وتُحفظ البيانات داخل ذاكرة التطبيق أثناء التشغيل. ولذلك فإن البيانات ليست مهيأة للحفظ الدائم أو للمشاركة بين جلسات متعددة بعد إغلاق التطبيق. كما أن نطاق النظام يركز على إدخال الرصيد الافتتاحي وإدارته داخل الشاشة، ولا يمتد إلى تنفيذ العمليات التشغيلية الكاملة الخاصة بالمخزون.

ومع ذلك، فقد صُمم هذا النطاق ليكون قابلًا للتوسع؛ إذ يمكن في المراحل التالية استبدال Mock Data بمصدر بيانات حقيقي، وتفعيل الحفظ الدائم، وإضافة آليات الاعتماد والصلاحيات، وربط الرصيد الافتتاحي ببقية وظائف نظام إدارة المخزون.
